# 话题自动选择与补充材料

更新日期：2026 年 10 月 20 日。应用版本 `0.4.0`，桌面协议 `1.2`，数据版本 `4`。

本文保留 `0.4.0` 的设计与真实分析记录。当前 `0.6.0` 加入启用选择：分析只可选择启用的 CLI，AGY 停用时界面明确改用下一家；发送前先检查至少三家参与者，避免分析后才发现人数不足。详见 [当前桌面操作](/Users/suchasplus/devs/agentic/newtc/docs/desktop-interactions.md)。

桌面现在把“准备话题”放在讨论前：读用户提供的材料，判断是否适合多方讨论，并在三种模式中选择。检查只做一次模型任务，生成结构化建议；调度和是否允许开跑仍由 Go 后台判断。

## 如何使用

新讨论默认“自动选择”。输入目标后可直接发送：后台先检查话题，符合自动运行条件时开始讨论。也可点击“检查话题与材料”先看结果，再发送复用这次检查，不重复调用模型。

| 任务特征 | 建议 |
| --- | --- |
| 比较设计、碰撞立场、权衡多个方案 | 自由辩论 `free_debate` |
| 判断具体主张是否成立，结合证据提出支持、反驳和裁决 | 证据裁决 `adjudication` |
| 匿名专家多轮评分、风险评估、优先级与路线图排序 | 匿名德尔菲 `delphi` |
| 目标、约束、上下文或评价标准不足 | `needs_clarification`，展示待补问题 |
| 简单计算、事实查询或单步执行，无需多方讨论 | `not_suitable`，提示不适合 |

分析卡显示推荐、信心、理由、待补信息、建议改写和材料缺口。`needs_clarification` 的“补齐后预计模式”只作参考，不作为运行模式。建议改写也不会自动替换原话题，只有用户点击采用才修改输入并使原检查失效。

自动开跑必须同时满足：检查完成；目标与材料快照完全匹配；推荐为三种具体模式之一；信心不低于 `0.6`；没有 `required` 材料缺口；检查未超过原 15 分钟期限；CLI 来源和当前配置匹配。信心是模型自报值，不是经过标定的正确率。手动选择模式可以覆盖建议，记录同时保留手动选择和原建议。

取消分析、更改输入、移除或新增材料、切换检查提供方、切换会话，都会废弃当前待用结果；过期异步响应不能自动创建讨论。关联讨论沿用父讨论的具体模式，继承冻结材料，并可新增材料。

## 为什么默认还是 Gemini

`til-consensus/runner/classify.go` 已公开分类 prompt、JSON schema 和 decoder，原高层分类入口默认 `gemini-api`，且要求 API provider。桌面复用 `BuildClassifyPrompt`、`ClassifyJSONSchema` 和 `DecodeClassifyOutput`，将传输接到已有的本机 CLI 适配层。

默认检查提供方为 `agy`，默认模型选择 ID 为 `gemini-3.8-flash-medium`，使用 CLI 自身已有登录。可以在检查提供方下拉框选 Codex、Claude Code 或 Grok Build，模型配置沿用桌面对应 provider 的设置和环境变量。无需为了分类再配置 Gemini API Key。CLI 不可用或返回无效结果时明确失败，不切换提供方、不退回 Mock、不自动重新请求。

Codex 通过现有 app-server；其余三家通过 til-consensus 的原生 CLI runner。真实验收发现 AGY/Gemini 不接受含空字符串的 enum，桌面仅为其原生传输宽化这一约束；prompt 与本地完整 schema 仍保留空字符串及合法模式枚举，返回后严格校验，未知值仍拒绝。分析任务最长 120 秒，独立私有工作目录，使用各 provider 原有只读或禁工具约束。分析卡分别记录 CLI 版本、请求选择 ID、实际报告模型、耗时和已报告 usage；CLI 未报告的模型或费用保持未知。

## 材料为何值得加入

只有一句 topic 时，分类器容易缺少目标、约束和成功标准。把需求、接口、日志或现有设计作为显式材料，有助于判断模式，也能让所有参与者依据同一份上下文讨论。

当前支持粘贴原文，以及系统文件选择框选取的 UTF-8 文本或代码文件。不会根据原文中的路径自动读文件，不递归扫描目录，不运行外部补充材料命令，也没有 PDF 提取、OCR、联网检索或自动事实核验。

| 限制 | 行为 |
| --- | --- |
| 最多 8 份，每份不超过 64 KiB | 超限报错，不截断 |
| 目标、标题与材料正文合计不超过 128 KiB | 分支另把父上下文计入总限额 |
| 有效 UTF-8，无 NUL，非空 | 二进制或其他编码需先转文本 |
| 文件字节与原文 SHA-256 一致 | 保留 BOM、CRLF、首尾空白；规范化标记为 `none-utf8` |
| 每份材料恰有一项摘要 | 拒绝未知、缺失或重复材料 ID |
| 关键点附逐字原文引文 | 本地验证 quote 是对应原文的精确子串 |

原始绝对文件路径不传入讨论。每份材料保存 ID、标题、来源、完整正文、字节数和 SHA-256。材料可以包含未证实内容，摘要会保留验证边界；逐字引用核对只证明引文来自该材料，不证明材料陈述属实。

原文随快照冻结，Codex 的 P0 和后续各参与者都接收完整冻结材料，恢复或关联讨论不再打开原文件。德尔菲在参与者视图清除路径、非白名单 metadata 及标题／来源中的已知身份标识；用户材料正文为保留原文证据不做文字替换，因此正文中的姓名、模型名或其他身份线索仍可能可见。父讨论的模型产物继续使用原匿名投影，本机所有者仍能查看原始审计记录。不能保证消除材料中的自报身份、隐晦身份线索或文风推断。

## 保存、期限与预算

Go 后台持久化独立 `preparations` 记录。相同 ID 和相同请求幂等复用；相同 ID 换输入或模型配置会拒绝。只有已完成、匹配且未使用的记录可以被讨论采用；创建 run 与标记 `usedByRunId` 在同一 SQLite 事务中完成，防止一份分析批准多个不同讨论。

采用的检查按一个外部 CLI 任务计入该 run 的 30 次额度和关联链的 90 次额度，usage 也并入讨论账本。未采用的检查仍有独立记录和可能的模型用量，不受某个 run 的 30 次额度限制。检查没有自动重试；一次 CLI 内部可能包含多次服务端 API 调用。

采用检查后的讨论期限从检查开始时计算，共 15 分钟，包括检查、等待和停止时间。超过期限需重新检查。后台退出中的检查取消，异常退出残留的 running 记录在重启后标为 interrupted，不悄悄重新调用模型。

数据版本升为 `4`，新增准备记录表；策略版本为 `m4-topic-preparation-v1`，保留对旧 `m3-cli-v1` 和 `m3-cli-v2-chain-budget` 冻结记录的兼容。JSON 导出包含材料原文、分析和冻结 hash；Markdown 包含推荐、理由、来源和材料指纹索引。私有原始诊断不进入 IPC 或导出。

讨论的“清理诊断”同时清理该讨论已采用检查的原始诊断，保留 SQLite 中的结构化分析、原文材料和账本。未采用的独立检查暂未提供单独的列表与清理界面。

## 验证方式

`npm test` 的准备流程使用显式 Mock 或固定响应回放，覆盖结构校验、逐字引用、输入变更、取消、消费原子性、预算、期限、材料恢复、匿名投影与桌面交互。Mock 有明确来源标记，不能代表真实分类准确率。

运行 `npm run verify:preparation:live` 会单独启动真实 CLI 后台，依次发出五次 AGY 分析请求，以本项目的 package.json、go.mod、engine-lock.json 验证三种模式及不能直接开跑的两类任务。脚本保存真实返回值、模型来源、usage 和材料 hash，不启动完整讨论，也不修改模型答案来满足预期。证据位于 `.tcview/preparation-validation/<时间>/`；首次或有源码改动时需先 `npm run build:host`。

可用 `npm run verify:preparation:live -- --cases=2,3,4,5` 人工指定本次待验证案例。脚本遇到模型或协议失败立即停止，不自动重试；更改提示词或接口后需人工重跑，旧失败证据不覆盖。

### 本次真实验收

通过本机 AGY `1.4.2`，实际报告模型 `gemini-3.8-flash-medium`，以真实项目文件完成以下准备检查：

| 案例 | 实际推荐 | 信心 | 材料数 |
| --- | --- | ---: | ---: |
| 本地持久化方案取舍 | `free_debate` | 0.95 | 1 |
| 两份模块声明的一致性主张 | `adjudication` | 0.95 | 2 |
| 专家匿名多轮优先级评分 | `delphi` | 0.95 | 1 |
| 未说明目标与约束的系统设计 | `needs_clarification` | 0.95 | 0 |
| 简单加法 | `not_suitable` | 0.95 | 0 |

最后两项尝试自动开始均被 Go 后台拒绝，验收没有创建任何完整讨论。材料全文指纹和引文精确子串另经离线核对。[汇总及逐项原始证据索引](/Users/suchasplus/devs/agentic/newtc/.newtc/preparation-validation/validation.json)保留全部来源。

五个成功案例来自两批证据，共发出 7 次外部 CLI 任务；另外两次失败分别为 AGY 原生 schema 空字符串枚举不兼容，以及 AGY 在被拒绝 RunCommand 后返回空结果。前者修正传输 schema，后者补强“只分类、不执行 goal”的提示词后，人工继续验证未完成案例，既有失败未覆盖。成功请求实测约 40–95 秒；这五例只验证功能链路，不代表分类准确率或稳定时延指标。没有自动重试或 Mock 回退。

Go 全包 race 及准备清理定向回归、7 项构建环境测试、7 项 stdio RPC 和 12 项 Electron 回归均通过。Electron/Go 自动化使用显式 Mock 或协议 fixture，与上述真实请求分别记录。macOS `0.4.0` 开发包已通过[精简 PATH 启动与后台重连验证](/Users/suchasplus/devs/agentic/newtc/.newtc/package-validation/2026-10-19T19-18-11.020Z/summary.json)。
