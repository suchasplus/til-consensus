# CLI 参与选择与桌面基础操作

更新日期：2026 年 10 月 20 日。TCView `0.6.0`，协议 `1.4`，SQLite 数据版本 `6`。桌面原名 NewTC，当前品牌统一为 TCView，内核名称为 til-consensus。

当前使用 macOS 用户数据目录 `~/Library/Application Support/TCView`，环境变量前缀为 `TCVIEW_*`，布局和折叠键前缀为 `tcview.*`。不读取或自动迁移旧 NewTC 数据和偏好，首次启动使用默认设置；旧目录保持原样。下文历史验收数值、截图与 `.newtc` 证据链接保留执行时的记录。

## 选择参与者

在“CLI 与连接检查”逐家修改“参与新讨论”开关，然后保存。四家默认启用；旧设置没有 `enabled` 字段时也视为启用。模型与推理参数的原有配置方式不变，详见 [CLI 设置说明](/Users/suchasplus/devs/agentic/newtc/docs/cli-settings.md)。

新讨论至少需要三家启用的 CLI：一位提案者、至少两位独立评审。可以保存少于三家或全部停用，但此时不能发起讨论；自动模式也会在花费话题分析额度前阻止发送。单独“检查话题与材料”只需要选定的分析 CLI 启用。

| 启用情况 | 提案与综合 | 独立评审 |
| --- | --- | --- |
| 默认四家 | Codex | Claude、Grok、AGY |
| 停用 Codex | Claude | Grok、AGY |
| 停用 Claude | Codex | Grok、AGY |
| 停用 Grok | Codex | Claude、AGY |
| 停用 AGY | Codex | Claude、Grok |

固定顺序是 Codex、Claude、Grok、AGY：第一位启用者提案，其他启用者评审。裁决模式由首位评审负责裁决、末位评审做语义复核；德尔菲按冻结的评审顺序分配匿名专家。界面在发送前显示角色，启动后连同模型、推理参数、版本和来源冻结。

停用表示不参加新讨论。应用不会在调用失败时自动替换参与者，不会改用 Mock。新讨论只检查已启用的 CLI，关闭的一家即使未安装也不会阻塞。冻结参与者全部必须完成有效评审或投票；自由辩论的关键主张仍至少需要两位独立评审支持，不会将提案者算作额外评审或降低身份、哈希和投票版本检查。

设置只影响新讨论和新的话题分析。运行中、停止后恢复中的讨论仍沿用冻结配置。旧讨论没有新角色字段时，继续解释为 Codex 提案及另外三家评审，原配置哈希和预算保持不变。新讨论策略版本为 `m6-provider-selection-v1`，恢复仍兼容 `m4-topic-preparation-v1` 和原有 M3 策略。

话题分析优先选择启用的 AGY。若它停用，则选择启用的 Codex、Claude 或 Grok；界面显示提供方的改变，已有准备结果失效。明确指定停用的提供方或采用来自已停用提供方的准备结果时，后端拒绝请求。分析失败不会暗中改用其他家。

## 优先级和检查

启用状态遵循 **环境变量 > 应用保存设置 > 默认启用**。`TCVIEW_CODEX_ENABLED`、`TCVIEW_CLAUDE_ENABLED`、`TCVIEW_GROK_ENABLED`、`TCVIEW_AGY_ENABLED` 可设 `true/false` 或 `1/0`；非法值或空值明确报错。Electron 的 `TCVIEW_*` 传递规则包含这些公共配置，未增加认证变量范围。

设置页标明已保存、当前有效与编辑中的启用状态，以及环境覆盖来源。被环境覆盖的开关可以保存应用偏好，但当前进程仍按环境值工作。恢复默认重新启用四家，环境覆盖继续生效。

停用项不会自动加载模型目录。仍允许主动重载目录、执行真实连接检查，以便修复后重新启用；手动检查会使用编辑配置和环境覆盖，且可能使用服务额度。停用状态本身不会伪造“连接通过”，CLI 的安装、版本及请求结果仍分别显示。

## 最近讨论与最近删除

历史搜索匹配标题和目标，可以清除搜索。最近讨论旁的删除按钮将记录移入“最近删除”，在该视图点击恢复可重新显示。删除当前查看项后切换到其他记录或新讨论；恢复只改变可见性，不启动模型调用。

删除提示提供“撤销”；也可以稍后进入“最近删除”恢复。`⌘K` / `Ctrl+K` 聚焦历史搜索，`⌘N` / `Ctrl+N` 新建讨论；设置弹窗打开时不会因快捷键丢掉设置编辑。聊天滚离底部后出现“回到最新”，便于阅读历史消息。

运行中及 CLI 尚在退出清理的讨论不能删除，需要先停止并等待退出。删除是可恢复的隐藏操作：保留 SQLite 快照、聊天、方案、检查点、诊断、证据、幂等键及父子关联。当前没有永久清空功能。

关联链预算计算始终包含删除项，所以删除父讨论或兄弟分支不会返还请求额度。已存在的子讨论仍保有原冻结上下文并可恢复；要从已删除的源讨论继续或新建分支，先恢复源讨论。重复请求若命中已删除的讨论，会提示恢复或使用新的请求标识，不会让记录悄悄重新出现。

协议新增 `run.trash`、`run.delete`、`run.restore`，事件为 `run.deleted` 和 `run.restored`。删除状态是可选的 `deletedAt` 字段，旧数据仍显示在最近列表。正常 `run.list` 排除删除项，底层存储的完整读取保留它们供预算和审计；导出包含删除标记与冻结角色。

## 收起讨论信息与输入区

上方默认只显示模式、流程阶段、运行状态和停止／恢复操作。点击“讨论信息”可展开参与者、模型和冻结角色；再次点击收起，隐藏部分完全释放高度。模式选择与关键控制始终保留在紧凑工具条中，人数不足的提示不会跟着隐藏。

下方的新讨论输入默认展开；成功发起讨论、从检查点继续或查看历史时，上下两块自动收起，为消息留出空间。“展开输入”可随时打开编辑区；已完成或停止的讨论在收起条上仍保留“新问题”和“补充要求，继续讨论”入口，点击后展开并聚焦输入。

底部输入区的箭头指示点击后的移动方向：“展开输入”向上，“收起输入”向下；顶部讨论信息保持向下展开、向上收起。

手动折叠不会丢失目标草稿、已添加材料、尚未添加的粘贴原文、分析结果或错误。收起条提示有未发送草稿／材料，分析中的“取消分析”保持可见。话题检查或发起失败时重新展开输入；点击示例、采用改写也会自动展开，不会把文字填入不可见编辑器。切换到另一讨论或明确新建讨论仍沿用原有的清空编辑行为。

讨论开始后只自动收起一次，流式消息到来不会反复覆盖用户手动展开的选择。折叠不更改模型、参与者、模式、预算和冻结配置，也不会停止讨论或发起新请求。顶部和底部支持独立展开，保留键盘操作和焦点；展开区域限高并可滚动。“回到最新”按钮按输入区实测高度定位，不再使用固定底部偏移。

`1440×920` 窗口的显式 Mock 讨论测得：两块展开时聊天区高度 `307px`，自动收起后为 `788px`，增加 `481px`。[布局实测](/Users/suchasplus/devs/agentic/newtc/.newtc/discussion-panels-validation/2026-10-20T06-02-06.270Z/layout-metrics.json)。完整 30 项 Electron 回归和类型检查通过，覆盖自动收起、停止恢复、草稿与材料保留、失败重开、历史、新讨论和窄窗；没有新增真实模型调用。

当时开发包已通过无本地内核覆盖的 `NEWTC_RELEASE=1` 构建、ad-hoc 签名及精简 PATH 的 CLI 探测／重连检查。原用户窗口已打开新版，并实际检查上下展开／收起；当前留在上下收起状态，Codex 话题分析选择与分栏宽度保持原值。[本轮汇总](/Users/suchasplus/devs/agentic/newtc/.newtc/discussion-panels-validation/2026-10-20T06-02-06.270Z/summary.json)。

## 调整三栏宽度

左右侧栏均可独立展开／收起：顶栏左侧按钮控制“最近讨论”，右侧按钮控制“讨论产物”；展开栏内部也有收起按钮。收起时侧栏和分隔线不再占据宽度，主讨论区可铺满窗口，顶栏的展开入口保持可见。左栏收起后顶栏补充“新建讨论”快捷入口，`⌘K / Ctrl+K` 会展开历史并聚焦搜索。

折叠状态自动保存在应用用户数据目录的本地存储 `tcview.side-panels.v1`，字段为 `leftCollapsed` 和 `rightCollapsed`，无需另外保存；退出重开继续使用。旧数据缺少该键或字段无效时默认展开。宽度单独保存为 `tcview.layout.v1`，收起不会把栏宽记成零；再次展开恢复首选宽度。当前讨论、方案版本、产物标签、历史搜索、未发送草稿和材料均不因折叠清除。

窄窗仍采用产物抽屉。仅因窗口变窄而临时隐藏右栏时，不覆盖用户的桌面偏好；用户明确打开或关闭抽屉会更新折叠选择。窄窗启动时不会自动弹出抽屉，避免遮住主讨论区；回到宽窗后沿用已保存的选择。查看决策会主动展开产物并转到投票页。macOS 左栏收起后，顶栏控件避开窗口红黄绿按钮。

本次完整 35 项 Electron 回归、类型检查和默认远端依赖构建通过。`1440×920` 窗口实测，左右栏展开时主区宽 `790px`，同时收起后为 `1440px`，增加 `650px`。回归覆盖独立折叠、退出重开、旧宽度恢复、坏数据回退、草稿与材料保留、当前讨论与产物标签保留，以及窄窗切换和键盘焦点。

当时无本地内核覆盖的 `NEWTC_RELEASE=1` macOS 开发包已重建并通过签名及精简 PATH 的 CLI 版本探测／后台重连检查。原生窗口实际收起两栏、退出重开后，两栏仍保持收起；未发送草稿随后恢复，AGY 检查提供方保持原值，没有发送模型请求。[本次验收记录与截图](/Users/suchasplus/devs/agentic/newtc/.newtc/side-panels-validation/2026-10-20T06-51-22.224Z/summary.json)。

拖动历史栏和详情栏旁的分隔条调整宽度，中间聊天区占剩余空间。历史栏默认 218px、可选 174–360px；详情栏默认 310px、可选 260–560px。实际最大值还会为聊天区预留宽度。

左右首选宽度自动写入 Electron 用户数据目录内的浏览器本地存储，键为 `tcview.layout.v1`。关闭重启后继续使用，不写入 CLI 配置。窗口缩窄时只调整显示宽度，不覆盖之前的大窗口首选值；宽度不超过 1030px 时保留现有讨论产物抽屉。存储不可用或格式损坏时使用安全默认值。
