# 系统通知与提示音

点击窗口顶部铃铛，打开“桌面通知”。这使用 Electron 主进程的原生系统通知，不是窗口内提示条。macOS 通常在桌面右上角显示通知；位置、样式、持续时间和锁屏预览由操作系统控制。

## 开关与保存

- “讨论结束时发送系统通知”和“播放提示音”默认开启。关闭通知会停止投递；声音选项保留，重新启用后可继续使用。
- 保存到 TCView 应用数据目录的 `notification-settings.json`，不修改全局 CLI、认证、系统音量或专注模式。macOS 默认目录是 `~/Library/Application Support/TCView/`；显式 `TCVIEW_USER_DATA_DIR` 仍有效。
- 新设置适用于之后发生的结束事件，包括当前正在运行的讨论。关闭对话框不保存编辑。
- “发送测试通知”只使用已保存配置，发送一条系统通知并按声音开关请求播放系统默认提示音，不调用模型、不消耗推理额度。有未保存修改时须先保存。

系统通知权限、专注模式、通知声音权限和静音设置可能影响横幅或声音。应用的“接口可用”只表示平台提供原生通知 API，不代表已获系统授权。测试显示 `shown` 表示系统已报告接收／显示，不能证明你实际看到横幅或听到声音；`failed`、`unsupported` 和 `timeout` 会如实展示。超时不会由应用撤销系统通知，迟到的系统回执会更新最近投递结果。

macOS 原生通知要求已签名应用。请使用构建生成的已签名 TCView 开发包验收；`npm start` 使用的 Electron 开发进程可能具有不同的通知身份。若未出现横幅，请在系统设置的“通知”中检查实际应用身份及其允许通知／声音选项。TCView 不会替你开启这些系统设置。接口依据见 [Electron Notification 文档](https://www.electronjs.org/docs/latest/api/notification)。

## 结束状态与点击行为

完成、失败、手动停止和中断都会发送通知。未达成共识、有效票不足、证据不足、需要人工决定及判定失败保留其真实分类，不包装成方案获支持。预算／期限耗尽以后台实际失败或判定结果为准。通知仅包含短讨论标题和固定结果分类，不发送材料正文、完整结论、CLI 原始错误或凭据。显式 Mock 讨论会标记 `Mock`。

同一讨论的同一次执行只提示一次；重复事件、后台轮询、重连及重新打开历史记录不会重复发送。恢复执行产生新的 attempt，结束后可以再次提示。初次加载已结束的历史记录不会补发旧通知。单纯断开 Go 后台连接不会被伪装为运行失败；重连后用真实快照确认状态。

点击通知会显示／恢复 TCView 窗口并打开对应讨论。主进程独立观察后台，不依赖当前选中的讨论；最小化、切到其他应用或停留在“新建讨论”时仍能收到提示。macOS 关闭主窗口后，应用及 Go 后台仍运行，通知点击可重新打开窗口。完全退出应用会停止后台，退出期间不再发结束通知；其他平台沿用其现有关闭／退出行为。

## 验证边界

`npm run test:notifications` 验证状态追踪、attempt 去重、快照竞态、声音参数、设置持久化和系统投递回执。专用 Electron 测试使用明确标注的原生投递替身，同时实际运行 Electron、preload、Go 与 SQLite；这些测试不代表实际弹出了系统横幅或播放声音。普通批量 Mock 回归显式关闭通知，避免向用户桌面刷屏。原生系统显示需另外使用已签名开发包验收。
