# M0 开发说明

本文保留 M0 的历史实现记录，运行示例、目录及后台入口名已按当前 TCView 同步。当前 `0.3.0` 已默认使用真实 CLI，当前启动与验收方式见 [实现说明](/Users/suchasplus/devs/agentic/newtc/docs/implementation.md)。复现下述模拟流程须显式设置 `TCVIEW_PROVIDER_MODE=mock` 并使用独立数据目录。

M0 验证桌面、后台与共识内核的连接。界面中所有 Codex、Claude Code、Grok 和 agy 发言均由 mock adapter 生成；模拟内容用于观察协议和恢复机制，不是对用户问题的真实模型分析。

## 运行方式

在项目目录执行 `npm install`，然后使用 `TCVIEW_PROVIDER_MODE=mock TCVIEW_DATA_DIR="$PWD/.tcview/mock-host" npm start`。开发时使用 `npm run dev` 并同样显式设置模拟模式；renderer 支持热更新，修改 Electron 主进程或 Go 后台后需重新启动。

环境变量均为本地开发配置：

| 变量 | 用途 |
| --- | --- |
| `TIL_CONSENSUS_DIR` | 固定基线的 til-consensus 源码目录；本地开发改动通过源码指纹标识 |
| `TCVIEW_RELEASE` | 设为 1 时要求内核为干净提交，禁止以本地补丁发布 |
| `TCVIEW_DATA_DIR` | Go 后台的数据目录 |
| `TCVIEW_USER_DATA_DIR` | Electron 用户数据目录，适合隔离测试实例 |
| `TCVIEW_MOCK_DELAY_MS` | 新 run 的模拟任务延迟，默认 500 毫秒；恢复使用原配置 |

默认后台数据保存在 macOS 的 `~/Library/Application Support/TCView/host`。SQLite 保存桌面快照和带单调游标的事件；协议检查点保存在 `engine-sessions`；每次尝试的输入、输出和 schema 产物单独保存。请勿在后台运行时手工删除数据文件。

## 进程和协议

Electron renderer 通过受限的 `window.tcview` API 调用主进程。主进程启动构建产物 `dist/bin/tcview-host`，使用逐行 JSON-RPC 2.0 通过 stdin/stdout 通信，stderr 仅供诊断。后台不监听本地 HTTP 端口。

协议版本为 `1.0`，主要方法为：

```text
hello
run.list
run.start      { goal, mode, idempotencyKey }
run.get        { runId }
run.stop       { runId }
run.resume     { runId, idempotencyKey }
run.events     { runId, afterEventId }
```

后台通知使用 `method: "event"`，`params` 为持久化的 DesktopEvent。协议字段定义见 [TypeScript 类型](/Users/suchasplus/devs/agentic/newtc/packages/protocol/src/index.ts)。单条输入帧最多 4 MiB。

`run.stop` 发出异步取消请求，后台随后通知停止状态。前端等到 `stopped` 或 `interrupted` 再允许继续。重复开始请求通过幂等 key 识别，运行 lease 阻止同一 run 并发恢复；后台进程还独占数据目录。

## 内核与 mock 适配

三种模式均调用 `consensus.NewEngine`，不是界面中的定时播放脚本。Codex 初稿在进入 Engine 前保存，完成内核执行后由确定性代码生成桌面结论。

DesktopDelegate 实现公开 `Dispatch / Await / Cancel` 接口。每次 mock 响应包装为 `coreOutput` 和 `desktopReview`，分别经过 schema 和引用校验；只有合法的 coreOutput 交给内核解码。任务输入被复制为独立快照，原始输出按 attempt 保存，取消中的任务留下未完成记录。

自由辩论由三位模拟评审参与，Codex 模拟起草和综合；裁决运行主张、质疑、验证和仲裁；德尔菲在界面展示匿名专家。所有结果都保留 Mock 标识，模拟验证不代表真实证据成立。

## 停止与恢复

P0、冻结请求和 session 映射先提交后运行内核。恢复从最后一个完整检查点继续；未完成并行轮次可能重跑，已有 attempt 不覆盖。已保存的 P0 不重复生成，已完成的内核只需补做最终判定。

默认期限为自开始起 15 分钟，停止等待时间计入，恢复不会延长原期限。过期后需要新建讨论。关闭窗口时 macOS 应用继续留在 Dock，后台可以继续；使用退出菜单或 Cmd+Q 退出应用时，后台取消任务并保留恢复状态。

## 验证入口

```bash
npm run test:host
npm run check
npm run build
npm run test:rpc
npm run test:e2e
```

Go 测试覆盖 delegate 校验、取消和并发，以及后台持久化、三模式和检查点恢复。RPC 测试启动真实二进制，核对协议、幂等和重启；Playwright 测试启动真实 Electron 窗口，经过 preload 和 stdio 完成讨论、停止继续与历史恢复。

## 当前边界

M0 尚未接入真实 CLI、逐字输出、文件附件、方案导出或安装包签名。原始输入只作为 mock 模板上下文，界面中的支持与裁决仅用于验证规则。用户变更需求通过新建讨论进行；关联 run 和完整方案历史交互在后续里程碑实现。
